## Context

`packages/hardware` 目前仅 `index.ts` 占位，无便携打印实现;`apps/mobile` 的 capacitor 配置极简（Camera/Geolocation/Preferences)，无 BLE/打印/推送。客户 API 只读 `GET /profile`，无资料编辑、地址管理(无 `customer_addresses` 表)、改密。发布侧无签名打包脚本、环境切换与验收文档，关键移动流程缺自动化测试。本变更补齐"增强(打印 + 客户自助) + 交付(发布 + 测试)"。约束:多租户/客户自身数据隔离;原生权限需可降级;遵循 CLAUDE.md（硬件抽象进 `packages/hardware`，业务进 `apps/api`/feature)。

## Goals / Non-Goals

**Goals:**
- 便携蓝牙打印:发现/连接打印机、打印取件/送达小票与标签、失败兜底与权限引导。
- 客户自助:编辑资料、地址 CRUD + 设默认、修改密码（带校验)。
- 发布交付:可签名打包、环境切换、版本与更新策略、真机验收清单与分发文档。
- 关键移动流程纳入自动化测试 + 真机验收门槛。

**Non-Goals:**
- 桌面 POS 的本地打印（已属 `apps/desktop`/POS，不在移动范围)。
- 推送通知与深链（独立后续，不在本变更)。
- 标签条码规范的全面标准化（先满足配送小票/标签的最小集)。

## Decisions

### 决策 1:蓝牙打印经 packages/hardware 抽象
在 `packages/hardware` 定义便携打印机抽象(发现、连接、打印小票/标签、断连处理)，移动端用 Capacitor BLE 插件实现该抽象;打印内容用 ESC/POS 指令拼装，提供取件/送达小票与标签模板。
- 理由:硬件细节集中、跨端复用，符合 CLAUDE.md（硬件抽象在 `packages/hardware`)。
- 备选:在 mobile-web 直接调 BLE（否决:硬件逻辑散落、难复用)。

### 决策 2:新增 customer_addresses 表
客户地址用独立表 `customer_addresses`(tenant、customer、label、地址、经纬度可选、isDefault、软删)，支持多地址与默认地址;预约/配送地址可引用。
- 理由:一个客户多地址是常见诉求;独立表便于扩展与复用。
- 备选:客户表内单地址字段（否决:无法多地址)。

### 决策 3:改密走移动认证体系
改密复用移动认证(客户凭证)，要求校验旧密码或已认证态，更新口令哈希并使现有 refresh token 失效(可选强制重登)。
- 理由:与现有 `/mobile/auth` 一致，保证安全。

### 决策 4:环境切换与版本策略
通过构建期环境变量切换 API 基址(dev/staging/prod);移动端记录版本号与最低支持版本，提供"需更新"提示策略;打包签名脚本纳入仓库脚本但密钥走安全注入(不入库)。
- 理由:多环境验收与灰度需要;签名密钥安全合规。

### 决策 5:自动化测试 + 真机验收作为发布门槛
关键移动流程(登录、客户下单查看/支付入口、配送状态/凭证/签收、打印)需有组件/E2E 测试;发布前执行真机权限与核心流程验收清单。把"测试通过 + 真机验收"作为 `mobile-release` 的发布前置要求。
- 理由:移动端目前仅后端 smoke，前端/真机覆盖不足。

## Risks / Trade-offs

- [蓝牙连接不稳定/机型差异] → 抽象层做重试与降级，连接失败有明确引导;先支持主流机型与打印机。
- [权限被拒导致功能不可用] → 权限文案 + 失败兜底（如打印不可用时提供其他凭证方式)。
- [地址表新增影响既有预约/配送地址] → 地址引用可选,旧的文本地址保持兼容,逐步迁移。
- [签名密钥泄露] → 密钥不入库，走 CI/本地安全注入;文档说明流程。
- [真机验收成本高] → 用清单标准化 + 优先核心流程，自动化覆盖回归。

## Migration Plan

1. 后端:新增 `customer_addresses` 表与客户资料/地址/改密接口。
2. 共享:`packages/hardware` 打印抽象 + 移动端 BLE 实现与权限声明。
3. 前端:资料/地址/改密界面与打印入口。
4. 工程:补组件/E2E 测试、打包签名脚本、环境配置与发布/验收文档。
5. 真机验收并出分发包(APK / TestFlight)。
- 回滚:各能力相互独立，可分别上线/回退;打印与地址为增量,不影响既有只读资料与配送。
