# 物品目录与 POS 属性选择验收

## 范围与操作入口

- SaaS：设置 → 物品目录，路径 `/saas/config/platform-settings/item-catalog`。超级管理员维护类型与具体物品的中、英、法名称、描述、启用状态和排序；支持人员只读。
- 租户：新建租户表单和租户详情页中的「可用物品目录」。可以按类型或逐项勾选；详情页的目录使用独立保存按钮。
- POS Web / Android：追加工单项目先选择类型和具体物品，再选择租户已有的适用服务。物品目录不生成服务或价格。
- Android：颜色、品牌、材质支持搜索、预设和自定义输入；自定义品牌按租户保留最多 50 条、90 天；瑕疵、特殊要求和备注支持常用词条切换，并保留手写内容。

处理类型仍使用稳定的 `cloth`、`shoe`、`carpet`、`car` 标识；显示名称由数据库提供。本次支持编辑这四类及新增其下的具体物品，不新增第五种处理类型。

## 数据迁移与兼容

数据库迁移 `0072_swift_mentallo.sql` 建立平台类型、物品目录、租户勾选配置及工单名称快照字段，初始化四类、20 项可编辑物品。

已有租户的选择保持 `null`，表示兼容模式，继续使用启用的目录，并允许旧客户端沿用原录入方式。SaaS 保存显式选择后，新项目必须携带有效的物品 ID；旧 APK 没有选择器时会收到升级提示。显式选择不会自动包含以后新增的物品，需重新勾选。

停用代替删除，历史工单保留当时的类型、物品名称。修改颜色等其他属性不会重写原名称；原离线请求的幂等重试也不受后续目录变更影响。

建议发布顺序：备份数据库 → 执行迁移 → 更新 API → 更新 Web → 发布并安装 Android APK → 配置租户可用目录。给现有租户保存显式选择前，应先更新其 POS 客户端。

## 验收步骤

1. 超管编辑类型的三种语言名称、描述和排序，新增具体物品并保存。刷新和切换语言后检查内容；未保存切换类型应提示。两个管理员同时编辑时，后保存者应收到版本冲突提示。
2. 创建租户时取消一个类型、选择部分物品，创建成功后进入详情确认选择一致。目录加载失败时应提示重试并阻止创建。
3. 在已有租户详情勾选类型、单项物品并保存。每个已启用类型至少选一项；清空全部表示不开放工单物品。支持角色不能保存。
4. POS 同步后仅显示该租户勾选且平台启用的类型、物品。没有可用物品、加载失败或未选择必填项时，显示明确提示，不能保存不完整项目。
5. 选择物品和已有服务，录入数量或重量、颜色、品牌、材质、瑕疵等字段后保存。确认金额仍使用租户服务价格，详情和客户物品记录保留正确名称。
6. 在 Android 搜索预设颜色、录入自定义品牌；重开弹窗和应用后检查品牌记忆。另一租户不能读取该品牌历史。常用词条可选中、取消且不会清空手写内容。
7. 停用已使用的物品或修改类型名称，检查新录入不能选择已停用项，历史工单显示原名称，历史项目仅修改颜色仍能保存。
8. Android 离线新增项目，重启应用后联网同步，确认物品 ID、名称快照与原请求一致，重试不重复生成工单项目。
9. 将本地数据库从版本 23 升级到 24，检查已有待同步收银、工单记录仍在；重新绑定终端后，旧租户目录缓存不能带入新租户。
10. 分别以租户、支持角色调用目录写接口，应拒绝；篡改未勾选物品 ID、跨类型物品 ID 应拒绝。已删除租户的目录读写应返回不存在。
