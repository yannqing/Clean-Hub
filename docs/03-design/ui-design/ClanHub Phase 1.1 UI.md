# CleanHub Phase 1.1 UI 设计出图文档

## 1. 设计目标

Phase 1.1 UI 示例图只用于表达 CleanHub 第一阶段产品界面方向，核心目标是展示“一家真实门店可以正常营业”的关键操作闭环：

客户识别 -> 收衣下单 -> 计价 -> 收款 -> 打印 -> 状态追踪 -> 取件 -> 日结。

本阶段 UI 不展示高级 BI、复杂多门店运营、完整 HR 排班、完整工单系统、完整营销平台、复杂库存和完整支付网关。

**注意：页面设计为：英文；页面中需要有转换语言的下拉框** 

**使用：Tailwind CSS v4 + shadcn/ui 风格组件库**

**Tailwind网址：https://tailwindcss.com/docs/installation/using-vite**

**shadcn组件网址：**https://ui.shadcn.com/docs/components/radix/card

## 2. 出图端口

| 端口          | 设计定位                                                |
| ------------- | ------------------------------------------------------- |
| SaaS 平台后台 | CleanHub 平台方管理试点租户、平台成员、基础运维         |
| 租户管理后台  | 商户 Owner/Manager 配置门店、员工、价格、服务和经营概览 |

## 3. 整体视觉方向

- 风格：现代、专业、稳定、低学习成本。
- 气质：偏 SaaS 运营工具，不做营销官网式大图英雄区。
- 信息密度：后台中高密度，POS 高可点按、高对比、高反馈。
- 主色建议：深青绿或清洁蓝作为品牌主色，搭配中性灰、白色和少量状态色。
- 状态色：灰色草稿、蓝色已收件、紫色处理中、绿色待取、深灰已交付、红色已取消

### 3.1 出图统一规范

- UI 文案默认使用英文，设计说明可使用中文。
- 后台页面强调表格、筛选、状态和操作入口
- POS 强调大按钮、金额、订单状态、打印、收款和离线反馈。
- 尽量不做大 hero，不做复杂 BI。

| 数据备份      | 平台级备份状态、备份记录、恢复申请入口    |
| 安全管理      | 登录策略、密码策略、会话安全、异常登录    |
| 个人中心      | 个人资料、语言、密码修改入口              |

### 4.2 出图页面

| 页面          | 出图重点                                                     |
| ------------- | ------------------------------------------------------------ |

### 4.3 SaaS 数据概览画面内容

首屏建议包含：

- 今日平台概览卡片：租户数、门店数、今日订单数、今日营业额。
- 租户状态分布：正常、停用。
- 待处理事项：待处理技术反馈。
- 近期平台活动：新增租户、租户启用/停用、平台成员变更。
- 快捷入口：创建租户、查看日志。

注意：

- 这里是基础平台运营摘要，不展示高级 BI、复杂趋势分析或收入结算。
- SaaS 平台后台应突出“平台治理”和“试点运行稳定性”，而不是做成财务分析大屏。
- 所有涉及租户停用、成员停用、权限修改、备份恢复的操作，都应在 UI 上体现二次确认和日志记录。

### 4.4 SaaS 平台 UI 设计重点

SaaS 平台后台应采用成熟云控制台风格：左侧稳定导航、顶部显示当前平台身份、主区域以表格和状态卡片为主。页面不应过度装饰，应强调信息密度、可扫描性和操作确定性。

设计上建议：

- 列表页默认提供搜索、筛选、状态标签和行级操作。
- 详情页采用“基础信息 + 运营摘要 + 风险提醒 + 最近活动”的结构。
- 日志、备份、安全管理属于一级能力，不应隐藏在个人中心或系统设置深处。
- 工单/技术反馈只作为 Phase 1 的轻量入口，不表现完整客服系统、SLA、聊天流或知识库。
- 数据备份页面只展示状态、记录和申请入口，不允许租户或普通平台成员直接恢复生产数据。

# 5. 租户管理后台 UI

租户管理后台面向洗衣店 Owner、Manager 和后台管理人员，核心目标是帮助租户完成门店、员工、价格、通知、设备和基础经营状态管理。Phase 1 不做复杂经营分析，而是优先保证门店可以稳定营业、配置可控、操作可追踪。

### 5.1 侧边栏结构

| 侧边栏页面         | 说明                                           |
| ------------------ | ---------------------------------------------- |
| 经营概览           | 今日经营摘要、订单状态、支付状态、待处理事项   |
| 门店管理           | 门店列表、门店详情、启用/禁用                  |
| POS 设备授权码管理 | 设备授权码、绑定门店、设备状态、最后同步时间   |
| 订单查询           | 订单号、客户、状态、金额、支付状态、取件时间   |
| 价格中心           | 衣物分类、服务项目、按件/按公斤价格            |
| 通知配置           | WhatsApp/SMS/Email 渠道开关、模板占位          |
| 企业资料           | 企业资料、联系人、默认语言、默认货币、票据信息 |
| 操作日志           | 改价、退款、删单、重印、开钱箱、员工停用等记录 |
| 数据备份           | 最近备份状态、备份记录、恢复申请入口           |
| 安全管理           | 密码策略、员工登录、设备授权安全、异常登录     |
| 个人中心           | 个人资料、语言、密码修改入口                   |

| 门店管理           | 所属门店列表、门店状态、门店详情、启用/禁用、营业时间        |
| POS 设备授权码管理 | 设备授权码、设备状态、最后同步时间、绑定门店、停用/重新生成  |
| 订单查询           | 订单号、客户、订单状态、支付状态、金额、取件时间、快速筛选   |
| 价格中心           | 衣物分类、服务项目、按件/按公斤价格、启用/停用、价格修改提醒 |
| 通知配置           | WhatsApp/SMS/Email 渠道开关、订单通知模板、发送记录入口      |
| 企业资料           | 企业名称、联系人、默认语言、默认货币、票据信息               |
| 操作日志           | 敏感操作记录、操作者、门店、对象、结果、操作原因             |

### 5.3 经营概览画面内容

核心卡片：

- 今日订单数。
- 今日营业额。
- 现金收入。
- Wave / Orange Money 待确认。
- 待取订单。
- 处理中订单。

图表建议：

- 支付方式占比。
- 订单状态分布。
- 今日订单时间轴。
- 待处理事项列表。

待处理事项建议包含：

- 待确认移动支付。
- 待取订单。
- 通知发送失败。
- 备份失败或备份超时。

不展示：

- 多门店排名。
- 利润分析。
- N vs N-1。
- 高级经营预测。
- 员工业绩排行榜。
- 复杂财务报表。

### 5.4 租户管理后台 UI 设计重点

租户后台应更接近企业经营配置台，而不是营销后台。页面需要清晰、稳定、可重复使用，方便店主和经理每天查看经营状态、维护价格、管理员工和处理异常。

设计上建议：

- 经营概览首屏只展示当天最关键的经营状态。
- 门店、员工、设备、价格都应以表格为主，支持搜索、筛选和状态标签。
- POS 设备授权码是门店运行的关键入口，应单独作为侧边栏页面。
- 操作日志必须覆盖改价、退款、删单、取消订单、重印、开钱箱、员工停用等敏感操作。
- 数据备份页面对租户只展示自身备份状态和恢复申请入口，不提供直接恢复生产数据的危险操作。
- 安全管理需要同时覆盖账号安全和设备安全，因为 CleanHub 的风险不仅来自网页登录，也来自 POS 设备授权和门店终端同步。

## 6. Phase 1.1 UI 边界说明

Phase 1 的后台 UI 应体现完整 SaaS 产品的基础框架，但不应过度扩展。

本阶段应该表现：

- 平台方可以创建、查看、启用和停用租户。
- 租户方可以管理门店、价格、通知和 POS 设备。
- 双方都有日志、备份、安全管理入口。
- 所有关键配置和敏感操作都有状态、确认和可追踪记录。
- 概览页只做基础运营摘要。

本阶段不表现：

- 完整 SaaS 订阅计费。
- 高级 BI 和复杂趋势分析。
- 利润预测。
- 多门店排名。
- 完整客服系统。
- 自动化灾备恢复平台。
- 复杂自定义权限编辑器。
- 营销自动化和会员增长系统。
