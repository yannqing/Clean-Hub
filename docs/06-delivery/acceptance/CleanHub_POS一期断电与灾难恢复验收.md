# CleanHub POS 一期断电与灾难恢复验收

## 一期上线结论

断电安全是上线门槛，不是后续增强。验收目标是：在任意一次本地写入、API 请求或服务器提交期间直接切断 POS 电源，重启并重新进入原终端后，交易不会丢失、不会重复收款，并能继续同步。

## 保护层与实现

| 保护层 | 一期实现 | 验收证据 |
| --- | --- | --- |
| 持久本地存储 | CleanHub Desktop 使用 SQLite WAL，`synchronous=FULL`；浏览器和 iPad 使用 IndexedDB 严格持久事务；旧 localStorage/文件数据自动迁移 | 创建销售后在任意网络阶段切断终端电源，重启后待同步销售仍存在 |
| 写前日志 | POS 命令、完整 payload、租户/门店/终端/员工作用域、ULID、幂等键在请求服务器前写入本地队列 | 模拟服务器已提交但客户端未收到响应；重放返回同一业务结果 |
| 事务原子性 | 购物车结算通过 `/pos/orders/checkout` 在同一 PostgreSQL 事务中创建订单与初始付款；单独付款也使用数据库事务 | 在订单插入与付款插入之间注入异常，数据库中不得留下半笔结算 |
| 自动恢复 | 登录原终端后扫描作用域队列，按本地序列和依赖关系自动重放；失败项保留且不会阻塞无关交易 | 重启应用并联网，待同步数量最终归零；失败项展示错误并可重试 |
| 防止双重交易 | 订单 ID、操作 ID、付款幂等键均为稳定 ULID；支付幂等键与 Wave/Orange Money 流水号在租户内查重 | 对同一请求重复发送至少 10 次，只产生一条付款记录 |
| 离线销售队列 | 每项保存时间戳、单调序列号、重试次数、依赖和最后错误；跨标签页使用 Web Lock，跨进程由 SQLite/IndexedDB 原子化 | 断网连续创建 50 笔允许离线的销售，恢复网络后按顺序同步且无重复 |
| 购物车保存 | 每次修改立即保存，另每 30 秒检查点保存；页面隐藏和退出时再次保存；本地与云端取更新时间较新的版本 | 修改购物车后等待 30 秒或立即断电，重启后内容一致；已结算购物车不得复活 |
| 离线现金外设 | 最近一次终端硬件配置按租户/门店/终端缓存；现金交易入队成功后可离线开钱箱并打印带“离线”标记的小票；打印任务和钱箱脉冲都有持久防重状态 | 断网现金结算可开箱、打印；在打印或开箱脉冲期间断电，重启不得自动重复物理动作 |
| 服务器备份 | PostgreSQL 每 900 秒生成 custom-format dump，`pg_restore --list` 校验、SHA-256 校验、原子改名；本地保留 7 天并自动上传异机 S3；媒体每 5 分钟镜像异机 S3 | 备份容器健康；云端存在 dump、checksum 和媒体对象；执行隔离恢复演练成功 |

## 支付边界

- 现金销售可以离线完成并排队。同步前，本地队列是事实来源；联网后服务器以同一幂等键落账。
- Wave/Orange Money 必须联网发起或记录。网络中断且结果不确定时，不得生成新幂等键重试；恢复流程只能重放原请求并向服务商查询/核对原交易。
- 当前 Wave/Orange Money 流程是录入外部流水号后由经理确认。未来接入支付商 API/Webhook 时，仍必须沿用同一付款幂等键，并增加 provider intent 状态查询，不能把“超时”当成“失败”。
- 不允许离线销售的商品，在已知离线状态下会阻止提交；如果在线请求发出后连接中断，则保留写前日志做结果核对，绝不能删除不确定交易。
- 打印机和钱箱属于不可回滚的物理外设。状态停留在 `printing` / `opening` 代表结果不确定，系统会要求人工核对，不会为了“自动恢复”而重复打印或再次弹开钱箱。

## 服务器部署门槛

1. `BACKUP_S3_ENDPOINT` 必须指向不同云厂商或不同物理主机，不能指向同一 VPS 内的 MinIO。
2. 备份桶必须为私有桶，使用专用最小权限凭据、HTTPS、版本控制和供应商侧加密；建议设置 30 天生命周期。
3. VPS、网络设备和门店主 POS 必须接入至少 4 小时 UPS。UPS 是硬件门槛，应用代码不能替代。
4. BIOS/UEFI 配置来电自动开机；操作系统启用磁盘加密，并确保 CleanHub Desktop 在员工登录后自动启动。
5. 每月至少执行一次真实恢复演练，并记录 RTO。仅看到“备份成功”不等于可恢复。

## 运维命令

查看备份与异机同步健康状态：

```bash
docker compose ps postgres-backup postgres-backup-cloud object-storage-backup-cloud
docker compose logs --tail=100 postgres-backup postgres-backup-cloud object-storage-backup-cloud
```

对最新备份执行隔离数据库恢复演练（不会覆盖生产库）：

```bash
docker compose --profile tools run --rm postgres-restore-drill
```

## 断电验收矩阵

每个场景至少重复 10 次，并核对 POS 本地队列、订单表、付款表、库存流水和小票任务：

1. 商品刚加入购物车时断电。
2. 点击结算后、请求发出前断电。
3. 服务器完成订单但客户端尚未收到响应时断电。
4. 现金付款写入后、钱箱打开前断电。
5. Wave/Orange Money 请求超时或 Webhook 到达前断电。
6. 离线累计 50 笔销售，同步到第 1、25、50 笔时分别断电。
7. 备份写入过程中服务器断电，恢复后不得把 `.partial` 文件视为成功备份。
8. 主 VPS 完全不可用，从异机 S3 下载备份并在新主机执行恢复。

验收失败条件：丢失已确认交易、同一幂等键出现多条付款、库存扣减两次、已结算购物车复活、云端最近成功备份超过 30 分钟，或恢复演练无法在 RTO 内完成。
