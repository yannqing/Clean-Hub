# POS 多国税务上线核对

首发数据在 [cleanhub-phase1-country-tax-templates.json](./cleanhub-phase1-country-tax-templates.json)。这是 SaaS 管理员导入数据库的一次性配置数据，不是 POS 运行时税率常量。之后在 SaaS 平台设置中修改税率即可更新已经选用该模板的租户，无需重新部署；历史订单和关账 Z 报表保留原快照。

1. 部署 API、管理端和 POS Web，并先执行数据库迁移至 0069；Android 设备安装包含本次原生修改的新版 APK。
2. SaaS 超管打开平台设置 → 国家税务模板，选择上述 JSON 文件，核对 13 国内容后导入。导入在一个数据库事务内完成；任一国家或已选用模板的租户存在冲突时，13 国配置全部回滚。导入成功后确认 13 个国家都显示在列表中。
   也可以在该页面逐国填写国家代码、货币、税种名称、税类与分项税率并保存；页面提供「下载 JSON 填写模板」、文件上传和导入前预览。模板结构下载自数据库现有配置；数据库为空时下载的是待填写空白结构，不含预设法定税率。首发 13 国配置文件位于本手册同目录，管理员须先复核当地法规再上传。
3. 旧数据库可能已有 SN/CI 的不完整模板。导入前核查 CI 原 9% 类是否仍绑定商品；如有，先由店主确认并重新指定税类。系统会阻止带有被删除税类的模板发布，以免继续按旧率收银。
4. 新建租户时选择已配置国家；系统会采用模板货币与税务设置。已有租户切换国家时，租户和所有门店货币须与模板一致，且旧税类不能仍被商品使用。
5. 核对每家门店商品和服务的免税税类。JSON 中的免税说明只作配置指导，系统不会凭商品名称自动推断免税资格。
6. 分别用含税、不含税、免税、混合税类和加纳分项税做线上及 Android 离线交易；核对支付金额、小票、订单快照、财务报表和关账 Z 报表。离线终端须完成同步后才会取得新税率。
7. 在生产数据库对应的 API 环境运行 `pnpm --filter @cleanhub/api check:tax-readiness`。只有显示 `Tax readiness passed.` 才开放新交易。检查会列出缺少的国家模板、未应用模板或版本落后的活跃租户、货币不一致、模板外税类和缺失的税务登记号；不会修改数据库。测试种子租户若仍为 active 且没有国家，也会被列出，需要先补配置或明确退出生产营业范围。

新销售在 API 建单前会复查税务就绪状态；缺少模板、租户未应用、税号缺失或币种不一致时返回 HTTP 409 和稳定错误代码，不会创建订单或收款记录。POS Web 在结款按钮旁显示对应的中文、英文或法文提示并禁用结款；新版 Android APK 同样缓存就绪状态，离线时没有成功同步过税务状态也禁止生成收款命令。既有订单的后续收款仍可处理，避免把已经成立的应收款冻结。

收银员遇到提示时按下列责任链处理：租户国家缺失由 SaaS 管理员补充；国家模板缺失由 SaaS 管理员在平台设置填写或上传；模板未应用由店主在租户设置中选择并应用；税务配置不完整由店主在 POS 设置中启用税务并填写登记号；币种不符由管理员核对租户及全部门店币种。修复后终端必须同步，才恢复结款。「暂时无法验证税务设置」表示终端没有可信配置或配置读取失败，应先联网同步。

租户或 SaaS 管理员若手动修改某租户的税率、含税方式，或新建、修改、删除税类，该租户会退出国家模板的自动同步；若要重新接入，店主须在租户设置中再次选择并应用国家模板。只修改税务登记号不会退出同步。

这份首发配置以项目收到的国家表为业务输入。加纳采用用户确认的 20% 分项：VAT 15%、NHIL 2.5%、GETFund 2.5%，与 [加纳税务局计算器](https://gra.gov.gh/online-tools/tax-calculators/value-added-tax/) 一致。塞拉利昂货币改用当前的 SLE；[塞拉利昂中央银行](https://bsl.gov.sl/index.html) 已使用该代码。其他国家税率和各类免税资格由 SaaS 管理员按当地最新规定复核后发布。

报表中的订单税额及分项是**销售时的原始税额**，按订单创建日汇总；退款现金单独列示。普通部分付款退款没有商品税类明细，不能据此自动推断法定税额冲减。财务应依据退货／贷项凭证核定税务调整，不能把现金退款额直接当作税额冲减。
